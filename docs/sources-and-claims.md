## 哪些是本文的观点

- 对部分行业命名和传播方式的怀疑。
- 以合格交付成本衡量实际使用价值。
- 把拟人当作理解工具，不当作设计要求。
- 通过删减组件和对照实验判断复杂度是否必要。

这些观点可以被批评、细化或用反例推翻。本文没有给任何具体公司归因未经证实的融资动机。

## 哪些仍然是待验证的提案

- 任务契约、交接与验收模板是否改善某个任务的表现。
- 在何种场景下 reset 加交接比 compact 更合适。
- 独立模型 reviewer 是否比单 Agent 加确定性检查更划算。
- 结构化状态、直接 API 与批量搜索何时优于拟人协作流程。

本仓库尚无公开实测结果。示例中的任务数、轮数、成本和时限是实验设计参数，不是测量结果。

## 对原始笔记的关键校准

| 原始想法的方向 | 发布时采用的表述 | 原因 |
| --- | --- | --- |
| Agent 相当于人，LLM 相当于大脑 | 保留作入门类比，注明不等于生物实现 | 避免把比喻误当技术定义 |
| LLM 就是自主性 | 自主性取决于完整系统的控制与权限 | 一个组件不能代表全部系统行为 |
| 知识更多，所以必然超越人类 | 知识覆盖不直接推出通用能力和可靠性 | 推论缺少必要证据 |
| Agent 的最终目的都是 AGI | AGI 是方向之一，具体任务有独立价值 | 不同系统的目标并不相同 |
| 专家什么都知道，只能有问必答 | 保留成本比喻，删除全知与被动的绝对描述 | 模型有知识与行动边界，产品行为也不同 |
| Personal agent 和 harness 只是同一旧概念 | 区分个性化应用与运行系统，考察具体增益 | 两者不在同一分类维度 |
| 某个 bot 只是简单封装 | 不保留指向不明确的产品断言 | 原笔记中的「Grokbot」未提供可唯一识别的来源 |
| AI 公司为了融资炒作 | 作为对行业叙事的怀疑，不作公司动机事实 | 缺少可核查的具体证据 |
| Anthropic 主张 reset 而非 compact | 两种策略按任务比较，均需验证恢复质量 | 官方材料也讨论并使用压缩 |
| 多智能体拆开就解决自评失真 | 职责分离可能有帮助，但仍会共享盲点 | 名义上的角色独立不等于错误独立 |
| 一切仍然是 PE | PE 是一部分，执行机制还需系统实现 | 状态、幂等、预算与权限不是文字自动实现的 |
| 拟人限制发展 | 作为可检验的设计疑问保留 | 无法仅凭类比证明 AI 能力已经触顶 |

没有沿用未经逐项核对的模型型号和价格排名，因为本文讨论的是长期适用的工程问题，而非当前产品选购。
